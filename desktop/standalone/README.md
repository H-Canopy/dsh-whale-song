# 鲸歌统一桌宠（Windows）

桌面上只保留一只鲸鱼娘：自由拖放、透明区域点击穿透、可开关自主漫游、托盘显示/隐藏。她自动连接本机 DSH，沿用 DSH 插件的会话事件、气泡、钱包、音乐服务与对话入口。

## 启动

在仓库根目录运行：

```sh
npm install
npm run desktop:start
```

启动器自动清除子进程的 `ELECTRON_RUN_AS_NODE`，不会更改用户或系统环境变量。重复启动只唤出已有桌宠，不创建第二只。旧的 `desktop/windows` 入口也转向同一实例。

### 开机自启

用户报过「关机和休眠后必须手动重新启动桌宠」—— 查证当时启动文件夹、`HKCU\...\Run`、计划任务里**都没有**它，项目里也没有任何自启代码。现在两条路都能开：

- **托盘菜单 →「开机自启」**：勾选框读的是**真实注册表值**（不是另存一份设置），改它等于增删同一个 Run 项。
- 或跑一次 `powershell -ExecutionPolicy Bypass -File tools/register-autostart.ps1`。

实现上**没有**用 `app.setLoginItemSettings`，而是统一走一个 Run 项，值是
`wscript.exe "<userData>\start-pet-hidden.vbs"`。原因两条，都是踩出来的：

1. `setLoginItemSettings` 会写**另一个** Run 项。两边各写一份 ⇒ **开机会同时启动两只**，两个进程互相抢窗口。
2. 自启**不能直接指向 electron.exe**：DSH 会话带 `ELECTRON_RUN_AS_NODE=1`，系统环境里也可能残留；一旦存在，Electron 会以 **Node 模式**起来 —— 进程在、桌宠**静默不出现**，最难查。`start-pet.cmd` 先 `set ELECTRON_RUN_AS_NODE=`，`start-pet-hidden.vbs` 再用窗口样式 0 静默拉起，**不闪黑框**。

首次从旧版升级，请刷新一次 DSH 界面，使它读取更新后的前端脚本。桌宠会把自己的存活探测地址写入 `$DSH_HOME/dsh-live2d-pet.json` 的 `desktopEndpoint`，保留原有配置。DSH 页面通过已有的 `/dsh-pet/config` 热读取它，无需新增宿主路由。

桌面角色就绪并连接 DSH 后，DSH 页面暂停自己的模型和事件流，不再显示重复角色。桌宠退出、断连、渲染进程失去响应或崩溃后，页面自动恢复；仅凭一个遗留文件不会一直隐藏角色。正常退出清理自己的探测地址。

## 交互

- 左键单击角色会戳她，出现一次表情、弹动与气泡反应；左键双击打开并聚焦对话框。
- 在角色可见部分按下并拖动，搬动桌面窗口；移动达到 4 DIP 后按拖动处理，拖动不触发戳或对话。面板、工具栏与透明区域不发起拖动。
- 设置中的大小支持放大和缩小，桌面范围为 150–280，显示宽度最多 384 DIP；旧的超大设置启动时自动收回到上限。桌面窗口和画布保持固定，通过 CSS 调整显示尺寸，避免缩放清空画布及窗口反复重设。为底部工具栏留出空间，弹动中的视觉命中矩形与位置锚点分别更新。
- 鼠标经过透明区域时点击落到下面的窗口。页面鼠标移动与 40ms 全局检查均以当前系统光标判断穿透，避免延迟坐标反复覆盖状态；状态不变时不调用 `setIgnoreMouseEvents`，拖动中保持可交互。
- 通常不抢键盘焦点；打开对话或点击输入框时临时允许聚焦。重复焦点通知不重复激活窗口，关闭输入面板后释放；中文组合输入期间保持焦点与交互状态，确认候选的回车不发送草稿。
- 工具栏 `–` 与托盘将角色收起为可点击、可拖动的「🐋 大肥鱼」标签。点击标签或托盘展开；拖动标签不展开。收起期间暂停漫游、保留原位置与 DSH 单实例归属。
- 托盘「自主漫游」立即开关并保存。默认开启，空闲一段时间后平滑移动；靠近角色、拖动、打开面板、打字、DSH 工作、隐藏或低性能模式都会暂停。
- 当前模型是一套坐姿 Live2D 场景，漫游表现为整体平滑移动，没有虚构新的行走动画。
- 位置存角色在屏幕上的锚点，兼容旧 `[x,y]`，启动、变更分辨率或拔掉屏幕后恢复到可见工作区。

## 连接与独立模式

优先读取 `$DSH_HOME/dsh-live2d-pet-desktop.json` 中实际端口与通行证，验证 `/dsh-pet/state` 后才连接。托盘可指定桌面版/网页版，自动模式保持已有连接，避免无故切换会话。每三秒检查并自动重连。

桌面页面始终使用一个本机服务地址，因此 DSH 重启不会切换 localStorage，表情、布局等前端设置得以保留。代理只转发固定路由，凭证仅留在主进程，拒绝跨站写请求。

DSH 关闭时仍可显示模型、换表情/道具、拖动和漫游、读取系统媒体会话。会话、钱包、说话与本地音乐/电台服务需要 DSH，恢复连接后重新可用。

日志与位置：`%APPDATA%/DS-WhaleSong-Pet/boot.log`（UTF-8）、`pos.json`。壳设置在同目录 `settings.json`，包括 `roaming`、`lowPower`、`hostPref`。旧 `shapeWindow` 与 `fullscreenPrimary` 不再驱动运行时；窗口成型源码仅保留为独立诊断工具。

若出现“模型在动但拖不动/按钮点不了”，先看日志中的 `input pointerdown`、`input mousedown`、`drag-start`、`drag-end`，区分事件根本未到达和命中/拖动计算失败。调试控制台可用 `await dshPetNative.diagnostics()` 获取当前坐标、命中结果、穿透状态和快照新鲜度。诊断仅记录事件类型和位置，不记录输入框文字。

休眠/锁屏暂停动画；唤醒、解锁及启动后同步恢复原生输入与页面渲染，并等待新的渲染帧及输入快照确认。监控分别检查快照与实际绘制是否停更，恢复失败时最多自动重载一次；当前窗口未发送的文字保存在 sessionStorage，重载后恢复。托盘「重新载入她」仍是手动恢复入口。仅重新启动桌宠和模拟恢复已自动验证，真实系统休眠/关机后恢复仍需在本机复测。

## 源码与验证

见 `tools/shell-gen/README.md`。主进程与 preload 改模板再生成。

```sh
npm run desktop:generate
node tools/test-all.mjs
```

窗口行为测试执行真实主进程入口并隔离用户数据；DSH 代理测试使用真实 HTTP/SSE；单实例归属测试用真实 Chromium 验证退出和崩溃恢复。OS 层鼠标穿透和真人拖动手感仍需在 Windows 桌面复测，注入的浏览器事件不能代替这一层。
