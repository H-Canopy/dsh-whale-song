# sources/ —— 音源适配器插口（鲸歌 dsh-whale-song 增量）

> 目的：**不把任何音乐平台写死**。用户用哪个播放器，就用哪个；没有适配器也照样能用。

## 三层结构（为什么这样分层）

```
① 统一层（零适配器）：Windows 媒体会话（SMTC）
     读「在放什么」+ 控制 播放/暂停/上一首/下一首
     网易云 / QQ音乐 / 酷狗 / 咪咕 / Spotify / foobar2000 / PotPlayer / VLC / 浏览器…
     只要它往外发媒体会话，就自动可用 —— 这是"用户不用网易云也能用"的那部分。

② 点播层（本目录，按需适配器）：搜索 → 播放指定歌曲
     每家接口不同，必须一个平台一个适配器；没装 → 只是不能点歌，其它照旧。

③ 兜底层（不依赖任何平台）：本地音乐库 + 在线电台。
```

| 能力 | 能否统一 | 说明 |
| --- | --- | --- |
| 显示在放什么 + 播放/暂停/上下首 | ✅ 走 SMTC | 系统级，人人都有 |
| 搜索并点播指定歌曲 | ❌ 必须适配器 | 各家接口/签名/登录都不同 |
| 进度/时长/音量/封面 | ⚠️ 看平台 | 很多客户端不发 timeline（网易云就不发） |

## 一个适配器长什么样

放在本目录下的 `*.mjs`（**文件名以 `_` 开头的会被忽略**，`_template.mjs` 就是模板）：

```js
export const manifest = {
  id: 'netease',                 // 唯一 id：只能 [a-z0-9-]，2~32 位
  label: '网易云音乐',
  version: '1.0.0',
  author: 'H-Canopy',
  license: 'MIT',
  capabilities: ['detect', 'search', 'play'],   // 只能是白名单里的能力
  platform: ['win32'],           // 可选：不写=全平台
}

export async function detect(ctx)            { /* → {ok, reason?} 这台机器上有没有这个播放器 */ }
export async function search(ctx, q, limit)  { /* → {ok, items:[…]} */ }
export async function play(ctx, item)        { /* → {ok, url?} 交给客户端/系统去播 */ }
export async function launch(ctx)            { /* → {ok} 没在跑就启动它 */ }
```

## 能力白名单（宿主只给这些）

| 能力 | 含义 | 宿主会做的事 |
| --- | --- | --- |
| `detect` | 检测本机有没有这个播放器 | 允许读注册表 / 常见路径 / 进程列表 |
| `search` | 搜索曲目或歌单 | 允许**出网**（仅该适配器声明的域名，详见下） |
| `play` | 点播（交给官方客户端播） | 允许起进程/协议唤起（如 `orpheus://`） |
| `launch` | 启动客户端 | 允许起进程（**不得带调试端口等危险参数**） |
| `control` / `readState` | 遥控 / 读状态 | 走统一层 SMTC，一般**不需要**适配器实现 |
| `playlist` | 歌单/整单播放 | 会替换客户端播放队列，属于破坏性操作 |

## 硬规则（安全与边界）

1. **不碰凭据**：适配器不得读取/保存账号 cookie、密码、token；不得代替用户登录。
2. **不绕版权**：不得解析/解密音频、不得做"免费听 VIP"这类接口；会员判定一律交给官方客户端。
3. **不做任意代码执行**：宿主不 `eval`、不静默下载并执行远程代码；适配器只能是**已经在本目录里的文件**。
4. **路由仅回环**：所有为适配器新增的宿主路由只允许本机访问（它们会出网或起进程）。
5. **失败要说话**：任何做不到的事返回 `{ok:false, reason:'人话'}`，**不要假装支持**。
6. **声明即契约**：`capabilities` 里声明了某项，就必须真的导出对应函数 —— 本目录的加载器会校验，不通过就拒绝加载。
