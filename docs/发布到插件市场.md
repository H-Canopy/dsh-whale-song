`GITHUB_TOKEN` 需要的权限：

| 仓库 | 权限 |
| --- | --- |
| `H-Canopy/dsh-whale-song`（你的） | Contents: **Read and write** |
| `awesome-dsh-plugin/awesome-dsh-plugin` | Contents: Read and write + **Pull requests: Read and write** |

（或者一个 classic token 勾 `public_repo` 就够了。）
token 只从环境变量读，**不落盘、不写进 git config、不打日志**，推完还会把 remote 里的
token 换成干净地址。

不想给 token 也行：照下面的「手动三步」做，一样能上架。

> **Windows 提示**：`publish.mjs` 早期版本有两个 Unix-only 依赖（`-o /dev/null`、
> `sleep` 命令），在 Windows 上会报满屏 `curl: (23) client returned ERROR on write of N bytes`
> 然后崩在 `spawnSync sleep ENOENT`。**已修**（改用 Node 自带 fetch + 跨平台 sleepSync），
> 现在 Windows 上能跑通自检。

上面那套「以后怎么发新版本」的流程在**上游**跑过（2026-09-25 发过 `v0.2.0`）。
**本 fork 一次都没发过**，所以第一次走的时候：

- 市场门禁的「仓库满 1 天」这条**会先卡你**（仓库如果有更早的历史也不算——以**这个仓库**的创建时间为准）；
- 建议第一次**手动三步**走一遍，把每一步看清楚，成功一次之后再改用 `npm run release:github`。

**发新版本的两步**（仓库已上架之后）：

```bash
# 1) 跑测试 + 改 package.json 的 version
npm test && npm run test:all
# 2) 一键发布（脚本自动读 GITHUB_TOKEN；仓库已存在，会直接推 + 更新市场条目）
npm run release:github
```

> 上游文档里那段「把 token 存进 macOS 钥匙串」（`security add-generic-password`）
> 是 **macOS 专有**的，Windows 上用不了。在 Windows 上就用环境变量：
> ```powershell
> $env:GITHUB_TOKEN = '你的token'; npm run release:github

> 撤销：去 <https://github.com/settings/tokens> 吊销即可。

## github.com 连不上时怎么推代码

有些网络环境里 `api.github.com` 通、`github.com:443` 不通：`git push` 会卡住或报
`Failed to connect to github.com port 443`。这时用 REST 的 Git Data API 推（blobs → tree → commit → 改 ref）。
脚本会先比对 tree 哈希，对不上就拒绝推送，不做破坏性操作：

```bash
GITHUB_TOKEN=<带 public_repo 的 token> node tools/push-via-api.mjs [本地提交sha] [owner/repo] [分支]
```

推成功后 GitHub 上的 commit sha 与本地不同（提交者信息由 API 补齐），但**文件内容逐字节相同** ——
可以用 `git -c core.quotePath=false ls-tree -r <本地sha>` 与
`GET /repos/:o/:r/git/trees/<sha>?recursive=1` 逐文件比对 blob 哈希来验证。
