## 0. 一句话架构

```
Electron 主进程（main.js）
  ├─ 建一个 420×600 的**透明、无边框、置顶**窗口（她就是画在这个窗口右下角的一块）
  ├─ 起一个只监听 127.0.0.1 的迷你 HTTP 服务（server.mjs）给窗口加载页面 + 提供 /dsh-pet/*

拖动 = 主进程每 33ms 读一次全局光标位置，把窗口搬到「光标 − 按下时的抓手偏移」
```

## 1. 拖动（重点看这一段）

### 1.1 按下 → 触发拖动（`main.js:266`）

```js
ipcMain.on('drag-start', async (_e, at) => {
  // 入口诊断：能到这一行说明按下到了页面
  bootLog('drag-start: at=… win=… visible=…')

  const cc = clampPet(cb.x, cb.y, cb.width, cb.height)     // main.js:290
  dragFrom = { grab: await grabOffset(), n: 0, lastX: NaN, lastY: NaN, lastAt: 0,
               startedAt: Date.now(), w: …, h: … }         // main.js:293
  const STEP_MS = 33                                       // main.js:295 30fps 目标
  const startedAt = Date.now()                             // ⚠️ 必须在 tick 之前（否则 TDZ）
  const tick = () => { … }                                 // main.js:299
  dragTimer = setTimeout(tick, 0)
})
```

### 1.2 拖动循环（`main.js:299`–`335`）

```js
const tick = () => {
  if (!dragFrom || !win || win.isDestroyed()) { dragTimer = null; return }   // 唯一允许的 return
  const p = screen.getCursorScreenPoint()
  const wantX = Math.round(p.x - dragFrom.grab.x)      // follow 语义：位置 = 光标 − 抓手偏移
  const wantY = Math.round(p.y - dragFrom.grab.y)
  if (wantX !== dragFrom.lastX || wantY !== dragFrom.lastY) {   // 去重是**条件块**，不是 return
    const c  = clampPet(wantX, wantY, dragFrom.w, dragFrom.h)   // 夹取：保证她本体可见
    const x2 = c.x, y2 = c.y
    win.setBounds({ x: x2, y: y2, width: dragFrom.w, height: dragFrom.h })  // 尺寸写死按下时的值
    … bootLog('drag: cur= want= set= got= size= cost= gap=')              // 诊断
  }
  // 自校正节拍：以目标时间戳算下一次延时（Windows 计时器粒度 15.6ms 会把 setInterval(33) 拉成 46.8ms）
  dragTimer = setTimeout(tick, Math.max(0, STEP_MS - (Date.now() - startedAt) % STEP_MS))
}
```

**三个必须守住的点**（都有测试守门员，见第 5 节）：
1. `tick` 里**只允许 1 个 `return`**（守卫那处）。多一个 `return` = 循环再也不会被调度 = 拖动永久冻死；
2. 节拍**必须是自校正 `setTimeout`**，不能用 `setInterval`（会被系统粒度拉长 40%，实际掉到 ~21fps）；
3. `startedAt` 必须在 `tick` **之前**声明（放后面 = TDZ 抛错 = 拖动完全没反应）。

### 1.3 抓手偏移（`main.js:250` 附近，`grabOffset()`）

```js
async function grabOffset() {
  const p = screen.getCursorScreenPoint()
  const [wx, wy] = win.getPosition()
  return { x: p.x - wx, y: p.y - wy }        // 按下瞬间算一次
}
```
之后每帧 `窗口位置 = 光标位置 − 这个偏移`。**不要**直接把窗口位置赋成光标位置。

### 1.6 夹取：保证"她本体"可见（`main.js:239`–`256`）

```js
const PET_BODY = { w: 240, h: 209, offR: 10, offB: 49 }   // 她画在窗口右下角（实测）
function clampPet(x, y, w, h) {
  const wa = screen.getPrimaryDisplay().workArea
  const PAD = 8
  const minX = wa.x - (w - PET_BODY.offR - PET_BODY.w - PAD)
  const maxX = wa.x + wa.width  - PET_BODY.w - PET_BODY.offR - PAD
  const minY = wa.y - (h - PET_BODY.offB - PET_BODY.h - PAD)
  const maxY = wa.y + wa.height - PET_BODY.h - PET_BODY.offB - PAD
  return { x: clamp…, y: clamp… }
}
```
三处调用：拖动循环（`main.js:313`）、按下时纠正（`main.js:290`）、启动位置（`main.js:848`）。
**教训**：窗口 420×600、她只占右下 240×209。所以"窗口出屏"就等于"她出屏" ——
夹取必须按**她本体**算，否则会把她拖到屏幕外（真机出现过 `y=-50` → 她在 `y≈1044`，
而工作区只有 1019 → 她整只掉出屏幕，用户看到的就是"怎么拖都不动"）。

## 3. 点击穿透：**已经整套删掉**（这是修"闪 + 抓不住"的关键）

**旧机制（`main.js:134` 有它的墓碑注释）**：`setIgnoreMouseEvents(true,{forward:true})` +
每 90ms 轮询问页面"鼠标下面是不是她"，再按结果切穿透。

**为什么删**（真机日志证据）：
- `preload: mousedown` **0 条**、`mouseup` 却有 2 条 → `forward:true` 只转发**移动**、不转发**按键**，
  按下在"穿透"状态下被桌面吃掉；
- `ignore` 在 true↔false 之间反复翻转 → 每次切 `WS_EX_TRANSPARENT` 都是**整窗重新合成** → 用户看到的"闪"。
- 现象吻合：**"指针离她远时正常、贴近她就闪"**、**"抓透明区能拖、抓她形象不行"**。

**现在**：窗口永远可交互；"鼠标在不在她身上"只由页面里的 `hitTest` 判定（不涉及窗口样式切换）。
代价（写在注释里，不藏）：窗口左上角那块透明空白不再穿透，会挡住鼠标。
要收回来正确做法是"面板改向下弹 + `SetWindowRgn` 定型"，**不要**回到轮询。

## 8. 生成器踩坑记录（改生成物会被覆盖）

## 9. 当前的已知问题（请评审重点看）

1. **窗口尺寸在多次拖动间会累积增长**（真机：50 次拖动 422→440）。隔离实验
   `tools/probe/probe-size-creep.mjs`：即便每次 `setBounds` 都传固定宽高，60 步仍涨 2px。
   怀疑与 150% 缩放（`scaleFactor=1.5`）下位置取整有关。影响：画布 resize → 掩码重建 + 视觉跳。
2. **`cost` / `gap`**：拖动每帧 `cost=2~11ms`、`gap=28~40ms`（节拍 33ms 基本守住）。
   是否还有优化空间未知。
3. **窗口成型对齐**（差 ~100px，默认关）。
4. **`cursorFeed` 与拖动是否争预算**（未验证）。
