# 统一桌宠交接 · 2026-10-13

本轮目标由用户确认：将独立桌宠与 DSH 桌宠合二为一，最终只有一只桌面角色，支持自由拖放和可开关自主漫游。当前版本：插件 `0.4.7-song.1`，桌面壳 `0.2.0`。

## 当前实现

桌面主窗口使用同一套 `assets/pet.js` 和模型，通过稳定的本机服务地址代理 DSH 的状态、SSE、钱包、说话、取消、控制和音乐服务。DSH 专属能力使用现有宿主插件实现，认证票仅在主进程读取和转发。DSH 关闭时仍可独立显示、互动、拖放、漫游和读取系统媒体会话。

运行中的桌面壳将自己的存活探测地址写入 `.dsh/dsh-live2d-pet.json` 的 `desktopEndpoint`，保留用户其他配置。DSH 前端热读现有 `/dsh-pet/config`，只在桌面角色已就绪、连接已通过验证、输入快照仍新鲜时让出模型。让出时暂停渲染器和事件流；退出、断连、崩溃后自动恢复。正常退出清理自身地址，异常退出留下的地址不会导致永久隐藏。

**真机重要事实：DSH 官方桌面页的来源是 `dsh-app://app`。** 存活探测只允许已连接 DSH 的 HTTP 来源与该官方应用来源；对只读 GET 提供必要的 CORS 和 Private Network Access 预检。其他代理路由仍拒绝跨站访问。只有按普通网页来源测试会漏掉这个适配问题。

旧 `desktop/windows/main.js` 转向统一壳，重复启动使用同一个实例。工具栏 `–` 将角色收起为同一窗口内的「🐋 大肥鱼」标签，点击标签或托盘展开；标签可以拖动，拖动不会展开。收起时暂停漫游，只保留标签命中区域，DSH 中不出现第二只角色。

## 本轮修正的真实问题

- 旧拖动把页面的累计位移减去窗口屏幕坐标，混合了两个坐标含义。新算法消费相邻输入之间的差值，再更新实际窗口位置；夹取时仍消费输入，回拖立刻响应。
- 主窗口不再无条件拦截整个透明矩形。页面上报实时掩码与可交互面板，鼠标移动事件与 40ms 原生检查共同更新穿透；状态相同时不切样式，拖动中不穿透。
- 视线追踪单独通过 IPC 更新，避免用合成 mouseMove 混入真实拖动输入。
- 默认 `focusable:false`，仅输入框临时允许焦点；透明区域在输入期间仍可穿透。
- 位置存角色屏幕锚点，兼容旧 `[x,y]`；画布几何变化、分辨率变化、显示器移除时重新夹取。
- 启动配置原先放在 pet.js IIFE 后面，前端读配置时尚未定义；现放在代码前面。
- 超过 1,300 行的字符串补丁生成器改为完整版本化模板，避免叠加注入与静默覆盖。成型器保留作独立诊断，不参与运行时。

## 隐藏找回与输入迭代

随后用户报告 `—` 隐藏后找回角色无法点击/拖动，以及中文输入断字。此前修订的隐藏逻辑会由原生 hide 再调用页面 setHidden，页面再次发送 hidden，形成反馈循环；页面输入焦点通知还会反复执行原生聚焦。改为幂等状态切换、单向原生确认与去重聚焦，输入面板关闭时主动释放 DOM 焦点，并保护 IME 组合期间的交互和回车确认。

用户仍复测出恢复后无法操作，随后提出保留上游式隐藏标签并命名为「大肥鱼」。现改为保留主窗口，在页面内收起角色、显示标签，不再调用原生 hide；收起快照只上报标签，隐藏角色不参加命中判定，保存的角色锚点不变。恢复时重新上报掩码。页面转发鼠标与定时原生检查也统一使用当前系统光标，消除延迟坐标竞争。

拖动位置计算保留累计小数位移，仅在输出原生坐标时对齐，避免每帧取整丢失慢拖位移；松开时补齐最后的指针位置，边缘夹取仍立即消费输入，回拖无需等待。

真实 Electron 中已验证四轮收起/展开、持续 DSH 归属，以及中文组合与后续追加文字；测试屏蔽 `/say`，没有向用户会话发送内容。浏览器注入验证之外，另有 Windows `WindowFromPoint` 校验及系统鼠标按下/移动/松开验证角色拖动、标签拖动与点击展开。

2026-10-13，用户对运行中的 `351bbf4` 明确反馈「收起、展开、拖动和输入都正常」。这四项已通过真人复测，本轮隐藏找回与输入问题验收完成。100%/200% 缩放、多显示器等此前未完成的真机验证仍保留原边界，不将本次反馈扩展为全部体验验收。

## 左键手势与大小调节

用户后来再次反馈角色无法点击、菜单仍能使用，以及大小只能缩小不能放大。用户在排查期间确认拖动恢复；重载恢复并不能证明此前拖动偶发失效的全部根因。

明确修正：桌面壳原来在按下时接管原生拖动，却没有在无移动的松开中接回 `poke`，所以身体单击不产生反应。现在无移动的左键松开戳她，500ms 内同处再次点击打开并聚焦对话框；移动达到 4 DIP 则按拖动处理，不触发戳或对话。网页中的左双击也恢复为打开对话。

大小原来受固定约 420 DIP 窗口及前端 `maxWidthRatio` 限制。桌面模式改按显示器可用尺寸限制模型，通过受信任 IPC 调整主窗口；窗口尺寸变化后保留屏幕上的角色锚点并重新上报命中区域。显示器夹取额外为工具栏留出 48 DIP，放大后仍可使用底部按钮。菜单定位从未动画的布局尺寸计算，避免反复读回旧变换导致跳出窗口。

戳她的弹动使用 stage 动画。输入快照现在分别传稳定布局 `body` 和当前视觉矩形 `model`：前者用于位置保存及夹取，后者用于掩码映射，避免弹动造成窗口跳位。性能档切换也改用 Pixi 的逻辑 `screen` 尺寸，避免把物理画布尺寸重复当作逻辑尺寸缩放。

本机验证覆盖大小 150→360→600→720→150，模型与原生窗口均实际变化；性能档切换后画布比例正确。Windows 系统鼠标验证单击出现反应、双击聚焦对话框，真实 Electron 的收起恢复与中文组合输入回归通过，测试未向 DSH 发送消息。新增能力仍需用户对最新版复测，不能沿用上一提交的验收结论。

最后一轮系统鼠标复跑检测到外部光标移动以及额外按下，目标窗口保护中止了点击脚本，拖动位移断言也因此未通过。这轮不计为系统鼠标验收通过；已保留此前独立的单击/双击实测和最新版 19 组自动测试结果，等待用户复测实际操作。
